Цей документ містить план розвитку, завдання на наступні ітерації та додатковий функціонал для сервісу тактичного метеомоніторингу.

## План робіт на наступну сесію (Пріоритет №1)

### 0. Завершити підключення та синхронізацію з GitHub
* **Опис:** Дотиснути авторизацію Git Credential Manager / Personal Access Token та успішно виконати `git push -u origin main` у репозиторій `GrandpaHoggard/wind_to_the_east`.
* Перевірити автоматичний білд та збереження всієї кодової бази у хмарі GitHub.

### 1. Список обраних локацій («Обрані точки»)
* **Опис:** Можливість зберігати географічні точки з кастомними назвами для швидкого перемикання в один клік без повторного введення координат.
* **Функціонал:**
  - Кнопка зірочки/додавання до обраного поруч із поточною локацією.
  - Кастомні користувацькі назви (наприклад: *«Точка вильоту Альфа»*, *«Позиція 2»*, *«Резервний майданчик»*).
  - Підтримка збереження координат як у **WGS 84** (десяткові градуси), так і у військовій сітці **MGRS**.
  - Зручний випадний список (dropdown) або бічна панель швидкого вибору.
  - **Збереження даних:**
    - Для неавторизованих користувачів — збереження у локальній пам'яті браузера (`LocalStorage`) + можливість ручного експорту/імпорту списку точок (JSON / текстовий файл).
    - Для авторизованих — автоматична синхронізація з профілем на сервері.

### 2. Система облікових записів та авторизації (Login / Auth)
* **Опис:** Особистий кабінет користувача для захищеного зберігання налаштувань та синхронізації обраних локацій між різними пристроями (смартфон, планшет, робочий комп'ютер).
* **Можливості та варіанти реалізації:**
  - **Форми входу та реєстрації:**
    - Логін/пароль або безпечний вхід без пароля через Magic Link / Email.
    - Опціонально: Швидкий вхід через Google OAuth (в 1 клік).
  - **Архітектурне рішення:**
    - *Варіант А (Хмарний BaaS — Supabase / Firebase):* Швидка інтеграція безкоштовного рівня аутентифікації без навантаження на наш VPS, готова база даних для збереження точок користувача.
    - *Варіант Б (Автономний серверний бекенд у Docker на TheHost):* Легкий API-сервер (Node.js/FastAPI + SQLite/PostgreSQL) поруч із нашим Nginx-контейнером на сервері в Німеччині для повної незалежності від сторонніх сервісів.
  - **Захист даних:** Збереження паролів у вигляді хешів (bcrypt/argon2), JWT-токени сесій з безпечними cookies (HttpOnly, Secure).

## Метеорологічні та навігаційні покращення

### 4. Параметр «База хмар» (Cloud Base / Ceiling AGL)
* **Опис:** Визначення та відображення висоти нижньої межі хмар (AGL) як у UAV Forecast (наприклад: *1 400 м*, *1 300 м* або «—» за відсутності суцільної хмарності).
* **Можливості:**
  - Відображення у картці поточного стану та окремою колонкою у таблиці погодинного прогнозу.
  - Розрахунок за метеорологічними шарами (знаходження найнижчого шару з покриттям $\ge 50\%$) або через авіаційну формулу депресії точки роси ($h_{base} \approx 125 \times (T - T_d)$ м).
  - Підсвічування критично низької бази хмар для БПЛА (менше 300–500 м).

### 5. Відображення загальної хмарності неба проти локального шару
* **Опис:** У таблиці погодинного прогнозу та верхній картці показувати як загальну хмарність усього неба (Total Cloud Cover, що показує UAV Forecast), так і пошарову, щоб уникнути плутанини, коли на висоті 1500м небо чисте (0%), але над землею є хмари (50%).
